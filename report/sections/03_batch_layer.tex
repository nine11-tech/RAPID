\section{Batch Layer}
\label{sec:batch}

\subsection{HDFS Storage}

The batch layer starts with HDFS. Raw logs are stored under \texttt{/logs/year=2024/month=XX/data.csv}. Although the assignment example uses day-level folders, the implemented layout remains date-partitioned and replayable: the physical files are grouped by month, while each record keeps its \texttt{timestamp}, allowing Spark to compute daily and hourly views. This choice reduced file fragmentation while preserving the ability to analyze threats by date.

Batch outputs are written under \texttt{/data/cybersecurity/batch}. Parquet outputs provide auditability and reconstruction, while HBase tables provide fast reads for the API and dashboard.

\subsection{Spark Historical Analytics}

The Spark batch layer implements the historical tasks requested by the assignment:

\begin{itemize}
    \item \textbf{Top malicious IPs:} suspicious and malicious events are grouped by \texttt{source\_ip}; the job produces a reputation score based on counts, labels, attack indicators, and traffic volume.
    \item \textbf{Port scans:} TCP events are grouped by \texttt{source\_ip} and 5-minute windows; sources contacting more than 20 distinct destination ports are flagged.
    \item \textbf{Attack path analysis:} \texttt{request\_path} and \texttt{user\_agent} are analyzed for SQL injection, XSS, path traversal, and offensive-tool patterns.
    \item \textbf{Volume by threat:} \texttt{bytes\_transferred} is aggregated by \texttt{threat\_label} to correlate traffic volume with benign, suspicious, and malicious activity.
    \item \textbf{Threat timeline:} events are aggregated by date and threat label to show the historical evolution of threats.
\end{itemize}

\subsection{HBase Batch Views}

HBase stores the historical views needed by the API and dashboard. It does not store raw logs; it stores query-oriented results computed by Spark. This keeps the dashboard responsive and avoids rerunning batch jobs for each user query.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.86\textwidth]{figures/batch/hbase_tables_list.png}
    \caption{HBase tables used for the batch layer serving views.}
    \label{fig:hbase-tables}
\end{figure}

The most important historical view is \texttt{ip\_reputation}. It stores the source IP, total threat count, SQLi hits, XSS hits, traversal hits, tool hits, average bytes, and normalized reputation score. The API reads this view when answering \texttt{/threats/ip/<ip>} and combines it with Cassandra real-time evidence.

\subsection{Batch Layer Assessment}

The batch layer satisfies the assignment because it stores historical data in HDFS, computes all required historical detections with Spark, and materializes serving views in HBase. It also extends the assignment with multi-step attack correlation, which helps identify source IPs that perform several attack stages rather than isolated suspicious events.
