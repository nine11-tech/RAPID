\section{Conclusion}
\label{sec:conclusion}

\subsection{Summary of Achievements}

This project successfully demonstrated the design and implementation of a complete 
Big Data cybersecurity threat detection platform based on the \textbf{Lambda Architecture}. 
The main objective was to combine historical analysis and real-time monitoring in order 
to detect suspicious and malicious network activities efficiently.

\vspace{0.8em}

The developed system integrates several key Big Data technologies into a coherent 
end-to-end pipeline. \textbf{HDFS} was used for distributed historical log storage, 
\textbf{Apache Spark} for both batch and streaming analytics, \textbf{Apache Kafka} 
for real-time log ingestion, \textbf{HBase} for serving batch views, and 
\textbf{Apache Cassandra} for storing active threats detected by the speed layer. 
A \textbf{Flask REST API} and an \textbf{HTML/JavaScript dashboard} were also used 
to provide a unified interface for querying and visualizing the results.

\vspace{0.8em}

The platform was able to detect several important categories of cybersecurity threats, 
including \textbf{brute-force attacks}, \textbf{SQL injection attempts}, 
\textbf{Cross-Site Scripting signatures}, \textbf{port scanning activities}, and 
\textbf{abnormal data transfer patterns}. The real-time pipeline achieved an 
end-to-end alerting latency of less than \textbf{five seconds}, which confirms the 
suitability of the proposed architecture for near-real-time security monitoring.

\vspace{0.8em}

In addition to the rule-based detection mechanisms, a bonus machine learning component 
was implemented using a \textbf{Random Forest classifier} trained with Spark MLlib. 
The model achieved \textbf{92\% classification accuracy} on the 
\texttt{threat\_label} prediction task, showing that machine learning can be integrated 
into the same Big Data pipeline to enhance threat classification.

\subsection{Lessons Learned}

Several important technical lessons were learned during the development of this project.

\begin{itemize}
    \item \textbf{Historical analysis and real-time detection are complementary.} 
    The batch layer provides deep insights into long-term attack trends, while the 
    speed layer enables rapid detection of active threats. Combining both layers gives 
    a more complete view of the security situation.

    \item \textbf{Windowing is critical in stream processing.} 
    In Spark Streaming, choosing the right time window directly affects the accuracy 
    of detection rules. For example, brute-force detection requires carefully defined 
    time windows in order to avoid missing attacks that occur across window boundaries.

    \item \textbf{Storage design affects performance and scalability.} 
    HBase is suitable for serving historical batch views, while Cassandra is more 
    appropriate for recent and active threats due to its fast write performance and 
    support for time-based data expiration.

    \item \textbf{Class imbalance can affect machine learning results.} 
    The DuckDB analysis showed that the dataset contains a strong imbalance between 
    benign, suspicious, and malicious traffic. This means that a high accuracy score 
    does not always guarantee strong detection of minority threat classes.

    \item \textbf{Lambda Architecture is powerful but complex.} 
    Maintaining separate batch and speed layers improves flexibility and reliability, 
    but it also introduces additional complexity in development, deployment, and 
    synchronization between components.
\end{itemize}

\subsection{Limitations}

Although the implemented solution satisfies the main project objectives, some 
limitations remain. First, the detection rules are based mainly on predefined 
thresholds and known attack signatures. This approach is effective for common attacks, 
but it may miss more advanced or stealthy threats. Second, the machine learning model 
requires further improvement because class imbalance can reduce its ability to detect 
minority classes such as malicious and suspicious events. Finally, the current system 
was tested in a controlled project environment, while a real production deployment 
would require stronger monitoring, security hardening, and fault-tolerance mechanisms.

\subsection{Future Improvements}

Several improvements can be added in future versions of the platform:

\begin{enumerate}
    \item \textbf{Improve machine learning with SMOTE:} 
    Applying oversampling techniques such as SMOTE could help rebalance the dataset 
    and improve the detection of minority classes, especially malicious and suspicious 
    traffic.

    \item \textbf{Add multi-stage attack correlation:} 
    The system could be extended to detect complex attack chains, such as 
    reconnaissance followed by exploitation and lateral movement.

    \item \textbf{Integrate GeoIP analysis:} 
    Mapping source IP addresses to geographic locations would improve the dashboard 
    by showing the origin of detected threats on a map.

    \item \textbf{Use adaptive thresholds:} 
    Instead of relying only on fixed thresholds, the system could calculate dynamic 
    baselines for each network segment or IP address in order to reduce false positives.

    \item \textbf{Explore Kappa Architecture:} 
    A future version could simplify the architecture by using a replayable Kafka stream 
    as the main source of truth, reducing the need to maintain two separate processing 
    paths.
\end{enumerate}

\subsection{Closing Remarks}

In conclusion, this project shows that Big Data technologies can provide a strong 
foundation for modern cybersecurity monitoring. By combining batch processing, 
real-time stream processing, distributed storage, machine learning, and visualization, 
the proposed platform offers a practical and scalable approach to detecting network 
threats.

\vspace{0.8em}

The Lambda Architecture proved to be an effective design choice for this use case, 
as it balances historical intelligence with real-time responsiveness. The project also 
highlighted the importance of clean data pipelines, appropriate storage systems, 
well-defined detection rules, and clear visualizations for cybersecurity analysts. 
Overall, this work represents a solid foundation for building a more advanced and 
production-ready threat detection system in the future.
