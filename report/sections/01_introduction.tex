\section{Introduction}
\label{sec:introduction}

\subsection{Context and Motivation}

The rapid growth of networked systems, cloud platforms, web applications, and IoT devices has significantly increased the attack surface exposed to cyber threats. Modern attackers no longer rely only on manual techniques; instead, they often use automated tools, scripted scanners, botnets, and exploit frameworks capable of generating thousands of requests in a short period of time. As a result, cybersecurity monitoring systems must be able to process large volumes of heterogeneous log data while detecting suspicious behavior as early as possible.

\vspace{0.8em}

Cybersecurity logs contain valuable information about user activities, network connections, access attempts, transferred data, requested resources, and detected anomalies. These logs can reveal several types of attacks such as brute-force attempts, SQL injections, Cross-Site Scripting attacks, port scanning activities, abnormal data transfers, and malicious user-agent signatures. However, the main challenge is not only collecting these logs, but also analyzing them efficiently at scale.

\vspace{0.8em}

Traditional batch-only approaches are useful for historical analysis and forensic investigation, but they are not sufficient for real-time threat detection. If logs are analyzed only after a long delay, an attacker may already have exploited a vulnerability, moved laterally inside the system, or exfiltrated sensitive data. Therefore, modern cybersecurity platforms need to combine two complementary capabilities: the \textbf{depth of historical analysis} and the \textbf{speed of real-time stream processing}.

\subsection{Problem Statement}

The main problem addressed in this project is how to design and implement a scalable Big Data architecture capable of detecting cybersecurity threats from massive network logs while supporting both historical and real-time analysis.

\vspace{0.8em}

This problem can be summarized through the following question:

\begin{quote}
\textit{How can we build a Big Data cybersecurity monitoring system that stores large-scale logs, detects historical attack patterns, identifies active threats in real time, and visualizes the results through a unified interface?}
\end{quote}

To answer this question, the project adopts the \textbf{Lambda Architecture}, which separates data processing into three main layers: a batch layer for historical analysis, a speed layer for real-time detection, and a serving layer for querying and visualizing the results.

\subsection{Dataset Description}

The system was developed and validated using the \textbf{Cybersecurity Threat Detection Logs} dataset. This dataset contains labeled network log entries describing different events observed in a network environment. Each record includes several important fields such as the event timestamp, source IP address, destination IP address, protocol, action, threat label, log type, number of bytes transferred, user-agent, and requested path.

\vspace{0.8em}

These fields provide a rich basis for both rule-based detection and machine-learning-based analysis. For example, the \texttt{source\_ip} field can be used to identify suspicious hosts, the \texttt{request\_path} field can reveal SQL injection or XSS payloads, the \texttt{user\_agent} field can expose automated tools such as \texttt{sqlmap} or \texttt{nikto}, and the \texttt{bytes\_transferred} field can help detect abnormal data transfer patterns.

\subsection{Project Objectives}

The main objective of this project is to build a complete cybersecurity threat detection platform based on Big Data technologies. More specifically, the system aims to achieve the following goals:

\begin{itemize}
    \item \textbf{Store historical cybersecurity logs} in a distributed and scalable way using HDFS;
    
    \item \textbf{Analyze historical attack patterns} using Apache Spark batch processing, including malicious IP detection, port scan detection, SQL injection and XSS signature extraction, and traffic volume analysis;
    
    \item \textbf{Ingest logs continuously} using Apache Kafka in order to simulate a real-time stream of cybersecurity events;
    
    \item \textbf{Detect active threats in real time} using Spark Structured Streaming, including brute-force attacks, known attack signatures, and abnormal data transfer volumes;
    
    \item \textbf{Store processed threat intelligence} using HBase for batch views and Apache Cassandra for recent real-time threats;
    
    \item \textbf{Expose the results through a REST API} that combines historical and real-time threat information;
    
    \item \textbf{Visualize cybersecurity insights} through an interactive HTML/JavaScript dashboard.
\end{itemize}

\subsection{Threat Model and Detection Scope}

The detection scope of this project focuses on common and observable network-based threats. The implemented detection rules are inspired by well-known cybersecurity practices such as OWASP-style web attack detection and Sigma-like rule logic for identifying suspicious patterns in logs.

\vspace{0.8em}

The system targets the following categories of threats:

\begin{itemize}
    \item \textbf{Brute-force attacks:} detected when the same source IP generates multiple failed login attempts within a short time window;
    
    \item \textbf{SQL injection attempts:} detected by searching for suspicious payloads and patterns inside the request path, such as quotes, logical conditions, or known SQL injection signatures;
    
    \item \textbf{Cross-Site Scripting attacks:} detected by identifying suspicious script-related patterns in web requests;
    
    \item \textbf{Port scanning activities:} detected when a source IP attempts to connect to several different destination ports within a limited time window;
    
    \item \textbf{Abnormal data transfer:} detected when the volume of transferred data exceeds a predefined threshold in a short period;
    
    \item \textbf{Known attack tools:} detected through suspicious user-agent values such as \texttt{sqlmap} or \texttt{nikto}.
\end{itemize}

\subsection{Proposed Solution}

To meet these objectives, the project proposes a complete Big Data pipeline built around the \textbf{Lambda Architecture}. The \textbf{batch layer} stores historical logs in HDFS and processes them using Apache Spark in order to generate long-term security insights. The \textbf{speed layer} uses Apache Kafka and Spark Structured Streaming to analyze incoming logs in real time and trigger alerts with low latency. The \textbf{serving layer} combines the outputs of both layers and exposes them through a Flask REST API and a web dashboard.

\vspace{0.8em}

This architecture provides a balanced solution that supports scalability, fault tolerance, historical analysis, and near-real-time responsiveness. It also makes the system modular, since each component has a clear responsibility within the global pipeline.
